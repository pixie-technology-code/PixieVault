# Project Onboarding Workflow

Use this workflow to quickly understand a new project and generate documentation to help others get started.

## 1. Project Overview
Analyze the repository structure and provide:
- Project name, purpose, and main functionality
- Tech stack (languages, frameworks, databases, tools)
- Architecture pattern (MVC, microservices, etc.)
- Key dependencies and their purposes

## 2. Repository Structure
Map out the codebase organization:
- List all top-level directories with their purposes
- Identify where different types of code live (models, components, utils, tests)
- Highlight any non-standard or unique organizational patterns

## 3. Getting Started
Create step-by-step setup instructions:
- Prerequisites (required software, versions)
- Environment setup commands
- How to install dependencies
- How to run the project locally and run tests

## 4. Key Components
Identify and explain the most important files/modules:
- Entry points (main.js, index.py, app.tsx, etc.)
- Core business logic locations
- Database models/schemas
- API endpoints or routes

## 5. Development Workflow
Document the development process:
- Git branch naming conventions (if applicable)
- Coding style and linting rules
- PR/Code review process

## 6. Architecture Decisions
Identify important patterns and decisions:
- Design patterns used
- State management and error handling strategies
- Security or performance considerations

## 7. Next Steps
Create an onboarding checklist:
1. Set up development environment
2. Run the project successfully
3. Make a small test change
4. Run the test suite

## Output
Please generate:
1. `ONBOARDING.md` - Comprehensive project guide
2. `QUICKSTART.md` - Essential setup steps
